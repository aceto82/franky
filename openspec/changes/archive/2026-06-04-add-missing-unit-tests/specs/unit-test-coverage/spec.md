## ADDED Requirements

### Requirement: ProductoService unit tests
`ProductoService` SHALL have unit tests covering obtenerProductos, crearProducto, actualizarProducto (partial and full update), and borrarProducto (soft delete), including the ProductoNoEncontradoException cases.

#### Scenario: obtenerProductos returns active products
- **WHEN** `obtenerProductos()` is called
- **THEN** it returns a list of ProductoResponseDto for non-ELIMINADO products

#### Scenario: crearProducto saves and returns the new product
- **WHEN** `crearProducto()` is called with valid data
- **THEN** it saves a new Producto with ACTIVO estado and returns its DTO

#### Scenario: actualizarProducto updates only provided fields
- **WHEN** `actualizarProducto()` is called with partial data
- **THEN** only the provided fields are updated, others remain unchanged

#### Scenario: actualizarProducto throws on non-existent product
- **WHEN** `actualizarProducto()` is called with an invalid ID
- **THEN** it throws ProductoNoEncontradoException

#### Scenario: borrarProducto soft-deletes the product
- **WHEN** `borrarProducto()` is called
- **THEN** the product's estado is set to ELIMINADO

### Requirement: SucursalService unit tests
`SucursalService` SHALL have unit tests covering obtenerSucursales, crearSucursal, actualizarSucursal, and borrarSucursal, including exception cases.

#### Scenario: obtenerSucursales returns active sucursales
- **WHEN** `obtenerSucursales()` is called
- **THEN** it returns a list of SucursalResponseDto for non-ELIMINADO sucursales

#### Scenario: crearSucursal saves and returns the new sucursal
- **WHEN** `crearSucursal()` is called with valid data
- **THEN** it saves and returns the new sucursal DTO

#### Scenario: actualizarSucursal throws on non-existent sucursal
- **WHEN** `actualizarSucursal()` is called with an invalid ID
- **THEN** it throws SucursalNoEncontradoException

### Requirement: VentaService unit tests
`VentaService` SHALL have unit tests covering CrearVenta, obtenerVentasPorSucursalYFecha, and borrarVenta, including exception cases for missing sucursal, missing producto, and missing venta.

#### Scenario: CrearVenta creates venta with detalles
- **WHEN** `CrearVenta()` is called with a valid sucursal and producto IDs
- **THEN** it saves the venta and its detalles, returns the response DTO

#### Scenario: CrearVenta throws when sucursal not found
- **WHEN** `CrearVenta()` is called with an invalid sucursalId
- **THEN** it throws SucursalNoEncontradoException

#### Scenario: CrearVenta throws when producto not found
- **WHEN** `CrearVenta()` is called with an invalid productoId
- **THEN** it throws ProductoNoEncontradoException

### Requirement: AuthService unit tests
`AuthService` SHALL have unit tests covering login success, wrong password, and non-existent user.

#### Scenario: login returns token with valid credentials
- **WHEN** `login()` is called with correct username and password
- **THEN** it returns a LoginResponseDto with a non-empty token

#### Scenario: login throws on wrong password
- **WHEN** `login()` is called with correct username but wrong password
- **THEN** it throws CredencialesInvalidasException

#### Scenario: login throws on non-existent user
- **WHEN** `login()` is called with a non-existent username
- **THEN** it throws CredencialesInvalidasException

### Requirement: EstadisticaService unit tests
`EstadisticaService` SHALL have unit tests covering the best-selling product calculation, empty ventas case, and ventas with no detalles.

#### Scenario: obtenerProductoMasVendido returns product with highest total
- **WHEN** ventas exist with multiple productos
- **THEN** the product with the highest sum of cantidad is returned

#### Scenario: obtenerProductoMasVendido throws when no ventas
- **WHEN** no ventas exist in the database
- **THEN** it throws EstadisticaNoEncontradaException

### Requirement: JwtTokenProvider unit tests
`JwtTokenProvider` SHALL have unit tests covering token generation, validation of valid and invalid tokens, and extraction of username and rol.

#### Scenario: generateToken creates a valid JWT
- **WHEN** `generateToken()` is called with a Usuario
- **THEN** it returns a non-null, non-empty JWT string

#### Scenario: validateToken returns true for valid token
- **WHEN** `validateToken()` is called with a token generated by the same provider
- **THEN** it returns true

#### Scenario: validateToken returns false for tampered token
- **WHEN** `validateToken()` is called with an invalid/malformed token
- **THEN** it returns false

#### Scenario: getUsernameFromToken returns the subject claim
- **WHEN** `getUsernameFromToken()` is called with a valid token
- **THEN** it returns the username used during token creation

#### Scenario: getRolFromToken returns the rol claim
- **WHEN** `getRolFromToken()` is called with a valid token
- **THEN** it returns the rol name used during token creation

### Requirement: CustomUserDetailsService unit tests
`CustomUserDetailsService` SHALL have unit tests covering user found and user not found cases.

#### Scenario: loadUserByUsername returns UserDetails when found
- **WHEN** the user exists in the repository
- **THEN** it returns a UserDetails with the correct username and roles

#### Scenario: loadUserByUsername throws when user not found
- **WHEN** the user does not exist in the repository
- **THEN** it throws UsernameNotFoundException
